## 1. 阶段目标

Go Gin 服务启动、配置管理（YAML + 环境变量覆盖）、MySQL/Redis 连接、基础中间件、健康检查接口。

本阶段结束后：`GET /api/health` 返回 200，DB 和 Redis 均连通，Ctrl+C 优雅关闭。

## 2. 本阶段实现内容

| # | 内容 | 文件 | 说明 |
|---|---|---|---|
| 1 | 配置加载 | `internal/config/config.go` | YAML + 环境变量覆盖 |
| 2 | Gin 启动 + 优雅关闭 | `cmd/server/main.go` | 完整启动链路，SIGINT/SIGTERM |
| 3 | 路由注册 | `internal/router/router.go` | 全局中间件 + /api/health |
| 4 | CORS 中间件 | `internal/middleware/cors.go` | 允许前端跨域 |
| 5 | 日志中间件 | `internal/middleware/logger.go` | 方法/路径/耗时/状态码 |
| 6 | 统一响应格式 | `internal/handler/response.go` | 封装 Success/Error 函数 |
| 7 | 健康检查 | `internal/handler/health.go` | DB ping + Redis ping + 模型统计 |

## 3. 为什么这样设计

- **配置加载优先级**：环境变量 > YAML 文件 > 默认值。DB_DSN / REDIS_ADDR 通过环境变量覆盖，Docker Compose 和本地开发两种模式共用一个逻辑。
- **中间件先铺轨道**：CORS + Logger + Recovery 从第一天就注册，后续只新增业务中间件。
- **统一响应格式**：所有 API 返回 `{"code":0,"message":"ok","data":{...}}`，handler 只管业务 data。
- **优雅关闭**：监听 SIGINT/SIGTERM，依次关闭 HTTP Server → Redis → MySQL，避免容器环境无法优雅停止。

