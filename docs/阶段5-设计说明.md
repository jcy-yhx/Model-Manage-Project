## 3. 为什么这样设计

- **Redis 读今日、MySQL 读历史**：Overview 的 today 数据从 Redis 原子计数器读，total 从 MySQL SUM 查询（缓存 5 分钟），trend 对比昨日 Redis 快照计算变化百分比
- **Service 层负责数据聚合**：不把 Redis/MySQL 查询逻辑泄漏到 Handler 层。Handler 仅做参数绑定和调用 Service。
- **ModelService 注入今日指标**：`GET /api/models` 把 models 表的静态元数据 + Redis 中当日动态数据合并返回，前端无需二次查询
- **分页默认值收敛**：page 最小 1，page_size 最大 100，防御性落入 20

### Key 设计（数据来源）

```
stats:{date}:total_tokens       → overview.today.total_tokens
stats:{date}:total_requests     → overview.today.total_requests
stats:{date}:total_cost         → overview.today.total_cost
stats:{date}:success_count      → } success_rate = success/(success+fail+timeout)
stats:{date}:fail_count         → }
stats:{date}:timeout_count      → }
stats:{date}:total_latency_ms    → avg_latency = total_latency / requests
stats:{date}:model:{id}:tokens   → model_usage.models[].tokens
stats:{date}:model:{id}:cost     → model_usage.models[].cost
stats:{date}:model:{id}:requests → models[].today_requests
stats:{date}:model:{id}:latency_ms → models[].avg_latency_ms

MySQL SUM/COUNT:                 → overview.total.*
MySQL GROUP BY DATE(created_at)   → trend.points[]
MySQL api_usage_logs (JOIN)      → logs[]
```
