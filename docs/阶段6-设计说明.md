## 4. 为什么这样设计

- **组件细粒度拆分**（8 个组件）：每个组件职责单一，按模块独立开发调试。后续增加登录页、管理后台只需新增页面，Dashboard 组件不受影响
- **Pinia 集中管理状态**：所有数据源（overview/modelUsage/trend/logs/models/health）由一个 store 统一刷新，避免多个组件各自发请求
- **轮询通过 store.startPolling() 驱动**：组件只负责挂载/卸载时调用 start/stop，不关心轮询实现细节。未来升级 WebSocket 只需改 store 内部
- **vite.config.ts 代理 /api**：开发时前端 localhost:5173 自动代理到后端 localhost:8080，无需配置 CORS 白名单
- **调用测试区 = 面试高光时刻**：现场发一次 POST /api/chat → 查看结果 → Dashboard 数字自动跳动 → 完整闭环一目了然

## 8. 前端 TypeScript 类型定义

```typescript
// overview
interface OverviewData {
  today: { total_tokens, total_requests, success_rate, avg_latency_ms, total_cost }
  total: { total_tokens, total_requests, total_cost }
  trend: { token_change_pct, request_change_pct }
  model_count: { online, total }
}

// 模型用量
interface ModelUsageItem { model_name, tokens, percentage, cost }

// 趋势点
interface TrendPoint { date, tokens, requests }

// 日志
interface LogEntry { id, model_name, project_name, total_tokens, cost, status, latency_ms, created_at }
interface Pagination { page, page_size, total }

// 模型
interface ModelInfo { id, name, display_name, provider, status, input_price, output_price, today_tokens, today_requests, avg_latency_ms, today_cost }

// 健康
interface HealthData { db, redis, online_models, total_models, alerts }

// Chat
interface ChatRequest { model, messages }
interface ChatResponse { id, object, created, model, choices[], usage{cost} }
```
