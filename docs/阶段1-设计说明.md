## 3. 为什么这样设计

- **骨架先行**：目录结构按架构文档定义，后续各阶段只填充业务代码。目录对了，代码才不会乱。
- **Docker Compose 第一天就可用**：基础设施跑通后，后续只改代码不折腾环境。
- **前后端独立**：Go 和 Vue 各自有独立的 Dockerfile 和开发模式，互不耦合。
- **配置即代码**：`config.yaml` 定义所有配置项的默认值，环境变量覆盖机制从阶段 3 起实现。

## 8. 测试方案

```bash

docker-compose up -d

# 2. 验证 MySQL
docker exec -it mysql mysql -u root -proot123 -e "SELECT 1;"
# 预期：正常返回

# 3. 验证 Redis
docker exec -it redis redis-cli PING
# 预期：PONG

# 4. 验证 Go 项目编译
cd server && go build ./...
# 预期：无错误

# 5. 验证 Go 入口
go run cmd/server/main.go
# 预期：输出 "AI Gateway Console - server starting..."

# 6. 验证 Go vet
go vet ./...
# 预期：无警告

# 7. 验证 Vue 项目构建
cd web && npm run build
# 预期：vue-tsc + vite build 成功

# 8. 验证 Vue dev server
npm run dev
# 预期：Vite 在 localhost:5173 启动

# 9. 清理
docker-compose down
```
