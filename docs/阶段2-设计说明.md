## 1. 阶段目标

把架构文档第三章完整落库。建表 SQL + GORM Model + 种子数据。本阶段结束后，6 张表可查、5 个模型带定价、1 个可用 API Key。

## 2. 本阶段实现内容

| # | 内容 | 说明 |
|---|---|---|
| 1 | 完整建表 SQL | `migrations/001_init.sql`，6 张表 + 全部索引 + 约束 |
| 2 | GORM Model 定义 | `internal/model/` 下 6 个文件，Tag + TableName + 关联 |
| 3 | 种子数据 SQL | `migrations/002_seed.sql`，用户/项目/API Key/模型 |

## 3. 为什么这样设计

- **SQL 先行、Model 跟随**：DDL 是 ground truth，Model 是对 DDL 的 Go 映射
- **种子数据独立文件**：`002_seed.sql` 与建表分离，方便重置数据时不丢表结构
- **API Key 预置**：种子数据中放入 bcrypt 哈希后的 Key，阶段 4 可直接用来调试
- **Model 独立性**：每个表一个文件，后续扩展不互相污染

users ──< projects ──< api_keys
                          │
models ──< api_usage_logs >── projects

             daily_usage_stats

## 9. 测试方案

```bash
# 1. 执行建表
docker exec -i ai_gateway_mysql mysql -u root -proot123 ai_gateway < server/migrations/001_init.sql

# 2. 执行种子数据
docker exec -i ai_gateway_mysql mysql -u root -proot123 ai_gateway < server/migrations/002_seed.sql

# 3. 验证表
docker exec ai_gateway_mysql mysql -u root -proot123 ai_gateway -e "SHOW TABLES;"
# 预期: users, projects, api_keys, models, api_usage_logs, daily_usage_stats

# 4. 验证 users
docker exec ai_gateway_mysql mysql -u root -proot123 ai_gateway \
  -e "SELECT id, username, role FROM users;"
# 预期: 3 行

# 5. 验证 models（含定价）
docker exec ai_gateway_mysql mysql -u root -proot123 ai_gateway \
  -e "SELECT name, provider, input_price, output_price FROM models;"
# 预期: 5 个模型，价格正确

# 6. 验证 api_keys（哈希存储）
docker exec ai_gateway_mysql mysql -u root -proot123 ai_gateway \
  -e "SELECT id, key_prefix, LEFT(key_hash, 20) AS hash_preview FROM api_keys;"
# 预期: key_prefix = 'sk-example-k'

# 7. 验证 cost 字段类型
docker exec ai_gateway_mysql mysql -u root -proot123 ai_gateway -e "DESC api_usage_logs;"
# 预期: cost 为 decimal(10,6)
```
